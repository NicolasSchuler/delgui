# Contributing to delgui

Issues and pull requests are welcome. This file covers building, testing and the house rules;
[README.md](README.md) is the user guide, and [RELEASING.md](RELEASING.md) is the runbook for
cutting a release.

## Layout

| path | role |
| --- | --- |
| `crates/delgui-core` | delta and git invocation, ANSI→span parsing, hunk arithmetic, file watching — no GUI dependencies |
| `crates/delgui` | egui frontend: state, rendering, theme, fonts, keymap, hotkey |
| `docs/reference.md` | generated configuration and feature reference |
| `docs/research.md` | the measurements the design rests on |
| `dist-workspace.toml` | what a tagged release builds and publishes |

`delgui-core` is deliberately frontend-agnostic, so a terminal (ratatui) frontend stays a real
option rather than an aspiration.

## Build and test

You need Rust 1.87 or newer, `git`, and delta 0.18 or newer on `PATH`. On Linux, also install
the GUI build dependencies: `sudo apt-get install libgtk-3-dev libxkbcommon-dev libwayland-dev`.

```sh
cargo build --release
cargo run -- examples/config_before.rs examples/config_after.rs   # try it by hand
cargo test                                                        # whole workspace
cargo test -p delgui-core --test fidelity                         # delta-output regressions
cargo clippy --workspace --all-targets
DELGUI_BLESS=1 cargo test -p delgui docs::                        # regenerate docs/reference.md
```

The suite runs against **your installed delta**, not a fixture, and asserts among other things
that the parser understands every escape sequence delta emits. A delta upgrade that changes its
output is *meant* to fail a test rather than mis-render silently. The watch tests sleep on real
filesystem events, so the suite is not instant.

CI builds and tests on macOS and Linux against a real delta, with `-D warnings`, and also runs
weekly, so that a delta release which changes its output shows up as a failing test rather than
as a mis-render. [`examples/`](examples/README.md) holds small inputs for trying the app by hand.

## House rules

- **Do not run `cargo fmt`.** The code is hand-formatted in a deliberately compact style with no
  `rustfmt.toml`, so `cargo fmt --check` does not pass and a blanket reformat would reflow files
  unrelated to your change. Match the surrounding layout by hand.
- **Do not hand-edit generated files.** `docs/reference.md` is generated from
  `crates/delgui/src/docs.rs`: change that and re-bless with
  `DELGUI_BLESS=1 cargo test -p delgui docs::`, or a test fails. `.github/workflows/release.yml`
  is generated by [`dist`](https://github.com/axodotdev/cargo-dist) from `dist-workspace.toml`:
  change the config and run `dist generate`.
- **Explain why.** Comments explain *why*, especially where a line encodes a measured finding
  about delta or the platform. Commit messages follow the same rule: a short imperative subject,
  then prose explaining the reasoning and what a test now pins down. User-visible changes go
  under `[Unreleased]` in [CHANGELOG.md](CHANGELOG.md).

## Before changing the design

Read [`docs/research.md`](docs/research.md). It records the measurements behind every decision
that looks arbitrary — and several that are worth knowing even outside this project. For
example, **delta infers syntax from the right-hand path only**, so `delta file.rs <(pbpaste)`
silently loses highlighting where `delta <(pbpaste) file.rs` keeps it.
